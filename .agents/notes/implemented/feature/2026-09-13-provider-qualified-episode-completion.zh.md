# Agent Note: Provider-qualified automatic episode completion

Status: implemented

## Problem

自动补集原来只能检查并选择性转存 115 分享。夸克到 115 导入器只能把整个已保存分享移动到 `/emby/_待整理`；直接连接会复制无关文件，并允许目标在重启后发生漂移。

## Decision

自动补集分别搜索 115 与夸克，检查每个实时分享树，并保留现有标题、年份、TMDB、季和集号证据规则。预检不执行 provider 写操作。同一集有多个可用资源时显示为冲突；操作者必须选择带 provider 的资源后才能转存。

115 叶子继续通过选择性分享转存处理。夸克叶子创建持久子任务，其中仅包含选中的源 ID 与预期集号。在执行任何夸克转存前，子任务重新验证已配置的夸克目标、当前 `c115_cid_map`、固定 115 账号、Emby 媒体库、规范 Series 路径与 TMDB 身份，以及 115 中准确的直接子目录。该绑定及全部传输检查点在重启和重试期间不可变。公开任务请求不能提交这些内部绑定字段。

夸克分享响应并不总是包含 `revision`。缺失时，适配器根据源 ID、名称、大小及对象类型生成确定性的非敏感版本指纹；子任务在转存前要求新分享快照产生相同指纹。115 目录清单短暂为空时最多重试 29 秒，而同名目录重复仍立即失败。若夸克以大文件限制响应拒绝浏览器身份下载，签名地址获取会使用官方桌面客户端身份重试一次，并在 CDN 请求中保持相同身份。下载把中转文件切成 10 MiB 分片，不超过当前夸克签名下载响应声明的范围上限，并通过并行范围连接获取；并发数由已验证设置 `quark_download_connections` 控制（默认 4，最大 8，实测 8 条低于 4 条）。每个分片先 fsync 再写入检查点，之后才会被再次领取；分片检查点与中转文件路径都以源对象为键，因此重试会复用更早尝试已下载的字节，而中转文件字节缺失时会使原有已完成分片检查点失效。上传前会再次用完整文件 SHA-1 校验夸克源身份。每个分片请求自带超时，因此静默的 CDN 连接会失败并重新打开，而不会把唯一的传输 worker 卡住。中途断流的分片会从已写入字节处重新打开范围，最多尝试四次，因为 CDN 会发出瞬时的 HTTP/2 流错误。目标验证把缺失的同名对象视为仍在发布并继续等待，只要 115 仍显示 CloudDrive2 的 `<name>**..uploading` 占位条目就延长等待，因此大量上传积压也能排空而不会失败；在没有任何可观察进展的完整静默期（下限两分钟，每 MiB 加一秒，上限三十分钟）或总计四小时之后放弃，以先到者为准。已存在但目录类型、父目录、名称、大小或 SHA-1 不同的对象属于另一个文件，会立即失败，冲突对象永不被覆盖。上传步骤使用从中转文件计算出的摘要，而不是下载前的数据库行；缺少已知中转摘要的导入会在联系 provider 之前失败。仅 Cookie 的 115 回退路径平铺发布到固定的 `/emby/_待整理` 暂存目录，因为 CloudDrive2 FUSE 挂载把新建子目录报告为 root 所有且不继承 ACL；`ensure-transfer-access.sh` 由服务单元与每分钟的 CloudDrive 监控为服务账号授予暂存目录与追更目录的访问权限。

夸克短期 `__puus` Cookie 可能在普通网盘 API 仍健康时过期，导致所有签名 CDN 范围请求返回 HTTP 412。收到该响应后，网盘 facade 会串行执行一次刷新：先用最新持久凭据重试；仍为 412 时，仅从一次有界根目录列表请求中移除过期 `__puus` 以获取替代值，不暴露地持久化后再次请求原范围。其余稳定浏览器 Cookie 字段保持不变。

绑定的子任务把文件直接上传到已验证的 Series 目录，验证每个 115 对象，同步 STRM，扫描 Emby，重新验证规范身份；任何选中集仍然缺失都会导致失败。父补集任务只报告子任务已排队，不会声称转存成功。

## Alternatives considered

拒绝按 provider 优先级静默选择第一个候选，因为这会隐藏多个合理资源。拒绝把整个夸克分享复制到 `_待整理`，因为这会传输无关剧集并丢失 Series 目标保证。拒绝在父任务内直接执行夸克传输，因为单 worker 无法提供独立、可恢复的检查点生命周期。

## Consequences

夸克自动转存需要默认夸克账号和 `quark_autofill_target_id`。选中的夸克文件会保留在夸克。操作者可以看到候选证据、冲突、已排队子任务 ID、字节和文件阶段、取消及保留检查点的重试。父任务完成但存在已排队子任务时不代表补集最终完成；子任务负责 provider、STRM 与 Emby 验证。
