# Agent Note: 已核对导入自动接力编目入库

Status: implemented

[English](2026-09-15-verified-import-automatic-ingest.md) | 中文

## Problem

手动夸克导入在全部文件进入固定的 `/emby/_待整理` 并通过 115 身份核对后就结束。移动、规范命名、STRM 生成与 Emby 入库仍是分离的维护工作，因此任务界面可能显示绿色的传输完成，但媒体实际上还不能在媒体库中使用。

全局规范化计划器不能安全地充当每次导入的自动接力。它清点完整的 115、STRM 与 Emby 目录，并且会按设计把没有现有 Emby 身份的 provider 文件保留为发现项；应用一份全目录计划还可能包含不相关操作。

## Decision

每个已核对且由用户手动提交的 `quark_to_115_import` 都确定性地排入唯一一个 `media_ingest` 接力。UUID 由来源任务 ID 派生，因此协调恢复与传输重试不会重复创建接力。自动补集绑定的导入继续使用既有的内联 STRM 与 Emby 验证，不再排入第二次入库。

接力任务只接受现有 Emby 电视剧身份。每个编号视频文件名必须与规范标题或原始 Series 标题一致，并且至少一个导入文件名还必须证明规范年份或 TMDB ID。必须且只能存在一个匹配的 Series，以及一个同名 115 Series 目录。任务在移动前按持久 115 ID、父目录、名称、字节大小与 SHA-1 重新验证每个源对象。

视频及相关字幕移入现有规范 Series 目录，并获得显式 `SnnEnn` 名称，同时保留发布版本后缀。名称被占用时，不同字节使用 SHA-1 后缀保留为可选版本；完全相同的现有字节继续留在暂存区，不覆盖也不删除。不支持的文件、无编号视频、有歧义的 Series 匹配及其他发现项继续留在 `_待整理`。

完成编排后，任务只同步匹配媒体库的 STRM 输出，运行可跟踪的 Emby 扫描，并针对原 Series ID 验证每个已导入且已播出的集号。缺少这项扫描后证据时任务必须失败。任务中心把传输与接力组合成一条七阶段流程，并把取消或重试操作指向当前子阶段。

## Alternatives considered

**每次导入后自动应用完整规范化计划。** 不予采用，因为计划负责整个目录，可能包含其他已审查操作，而且不能为尚未被 Emby 入库的新暂存文件推断身份。

**按分享标题创建文件夹并移动全部导入。** 不予采用，因为发布标题不是媒体身份，可能静默创建重复或错误的 Series 根目录。

**只运行 STRM 同步与 Emby 刷新。** 不予采用，因为 `_待整理` 被排除在媒体目录之外；扫描不能替代经过验证的规范媒体库移动。

**把传输与入库显示为不相关的执行卡片。** 不予采用，因为操作者需要一个可见的最终状态，且不能把文件传输误认为媒体库已可用。

## Consequences

只有当身份依据唯一且最终 Emby 集号证明成功时，手动夸克导入才是端到端完成。有歧义或不支持的内容仍会完成传输任务，但组合流程以明确的待检查发现结束；被拒绝的文件不执行 provider 修改。

队列新增一个内部接力任务类型、持久父任务引用、逐文件移动证据与扫描后结果。编目入库复用既有媒体修改串行化、provider 身份检查、STRM 边界与 Emby 完成跟踪，不引入另一个 scheduler 或数据库所有者。
